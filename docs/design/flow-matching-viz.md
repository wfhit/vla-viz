# Flow Matching 3D 可视化：分镜设计方案（10 步版）

> 依据：`flow-matching-understanding.md`（v2，主仓 commit 20b39c2 / PR #638）。
> 状态：**仅设计，暂不实现**。等第一个带印章的检查点 step_160000 落盘后再导出、做动画。
> 当前已提交的章节（1f7ca0f，"动作专家与流匹配" FM-0..FM-9）讲的是 v1 的 t=1 单步。本方案会**替换**它，并保留 v1 作为 K=1 对照。
> 约束不变：只用 k005b 真值；不用弹窗或大框覆盖层，一切在 3D 场景里演示；每根箭头都要有可见的源块和终块；3D 文字只用 ASCII；不改 FOV。

---

## 1. 核心决策

1. **画真实的 10 步。** 每一步的 x_t、te_k、γβ、联合注意力、v_k、x_{k+1} 都是导出的真实张量，不做插值伪造。
   - 唯一的"补帧"是步内动画 x_k − s·δ·v_k（s∈[0,1]）。它就是 Euler 更新式本身在 s 上的连续化，s=1 时逐位等于真实的 x_{k+1}。
2. **画出两个方向。**
   - **深度**：专家的 28 层，沿用已有的专家列。
   - **时间**：10 个 Euler 步，新增动作区的 "Euler 栈"。
   - 主干只在时间轴的起点出现一次，它的 K/V 缓存作为"锁定"块被 10 步共用。
3. **用理想直线作幽灵对照。** x*_t = (1−t)a + t·x_1 用到了标签，是真值，可以与真实 Euler 轨迹 x_{t_k} 同框比较。偏离多少就是模型的误差，不加修饰。
4. **v1 只做数字对照。** K=1（同一 step_160000 检查点）的 MSE 与 K=10 的 MSE 并列显示为 ASCII 标注。v1（step_130000）的 0.370 / 0.108 只写在文字解说里。
5. **不预设结论。** 例如"10 步比 1 步好"、"8 个粒子分簇"，都要以 step_160000 的实测为准，文案到时再填。

## 2. 导出（扩展 `tools/export_k005b.py`，step_160000 落盘后执行）

### 2.1 前置检查
- 读检查点的 `action_decode` 印章，逻辑与 `check_action_decode_stamp`（sft.py:401-432）一致：无印章且 K>1 就拒绝；law 不等于 `ACTION_DECODE_LAW` 也拒绝。导出日志写明 law 和 flow_steps。
- `model.flow_steps = stamp.flow_steps`（预期为 10）。

### 2.2 解码路径：自己写循环，逐步抓数据

```
enc = model.encode_prefix(...)                         # 一次
assert enc.behavior_fields == forward(...).behavior_fields
x = x1 (float32)
for k in range(K):
    t = 1 − k/K
    v = model.predict_velocity(enc, state75, x, t)     # 在 trunk.forward_suffix_stream:268 处挂 hook
    record(k, t, x, v, ...)
    x = x − v/K
assert allclose(x, model.sample_action_chunk(enc, state75, x1)[0], atol=1e-6)
```

### 2.3 新增 / 改动的键

| 键 | 形状 | 用途 |
|---|---|---|
| `fm.K`、`fm.t[K]`、`fm.law` | — | 步数、时间表、印章 |
| `fm.x[K+1]` | 11 × 16×23 | 每一步的板（x_{1.0} … x_{0.0}） |
| `fm.v[K]` | 10 × 16×23 | 速度板 |
| `fm.ideal[K+1]` | 11 × 16×23 | 理想直线 x*_{t_k} |
| `fm.u`、`fm.a` | 16×23 | 目标速度和标签 |
| `fm.err[K]` | {mse_x, dev_ideal, v_err} | 每步诊断量 |
| `fm.te[K]` | 10 × 64 窗口 | 时间嵌入，场景里的窗口 |
| `E{i}.ada[K]` | 28 × 10 × [4,64] | 每层每步的 γβ 窗口 |
| `E{i}.attn[K]` | 28 × 10 × 17×49 窗口 | 每步的联合注意力（后缀 Q 对 [前缀可见列窗口 ‖ 17]） |
| `E{i}.mass[K]` | 28 × 10 × 17×4 | 状态/视觉/文本/后缀质量 |
| `E{i}.out[K]` | 28 × 10 × 17×64 窗口 | 层输出 |
| `fm.suffix_in[K]` | 10 × 17×64 | 后缀输入 |
| `fm.particles` | 8 × 11 × 16×23，以及 mass 8×10×28×17×4 | 8 个噪声的完整轨迹 |

体积估计：每项都小于 0.5 MB，合计约 3–4 MB JSON。确有必要时，attn 可以只导出 0/5/9 三步，作为降级方案。

### 2.4 断言清单
1. 自写循环的结果等于 `sample_action_chunk`（≤1e-6）。
2. K=1 解码等于 x_1 − v(t=1)。
3. `encode_prefix` 的 behavior_fields 等于联合前向的结果。
4. 理想路径端点 ideal[0] = x_1、ideal[10] = a。
5. 原有的 v1 断言（23 维布局、1211 可见列、settle 规则）保留。

## 3. 场景布局

- **主干列**：不动。新增一个 "KV cache" 锁定条：在 28 层的 K/V 块旁边加一圈细框和 ASCII 标签 `cached once`，从 FM-3 开始常亮。
- **专家列（28 层）**：保留。每层的 γβ 块显示的贴图按当前步 k 切换（`E{i}.ada[k]`）。
- **动作区：Euler 栈（新增）**。11 块 16×23 的薄板沿时间轴排开（t=1.0 → 0.0），每块下方标注 `t=0.9` 之类。
  - 当前步的板高亮，其余半透明。
  - 板旁是对应的 v_k 板，用发散色标。
  - 理想路径 x*_t 画成同位置的线框幽灵板。
- **回环（x_{k+1} 回到后缀输入）**：两个方案，见 §9。
  - **A（推荐）**：成对的 wrap 标签加一条登记过的边。与主干/专家列折行的做法一致，不画横跨场景的长线。
  - **B**：Euler 栈本身就是"展开的循环"。每块板向下一块板画短箭头，再从板到专家输入画一根箭头，并随 k 移动。这样没有回环线，但每步都会有一根移动的箭头。
- **按步切换贴图**：专家相关块的纹理按 step 索引选用，渲染器为每块准备 K 个纹理，或在切换时重新上传。

## 4. 箭头原则（沿用 1f7ca0f 的注册表和审计）

1. 所有箭头都要在注册表登记 `{src, dst, phases}`，源块和终块必须可见，审计结果 noIn/noOut 都为空。
2. 新边：
   - `x_k 板 → action_in_proj`；`te_k → time MLP`；`te_k → E_i.ada`；
   - `缓存 K/V_i → E_i.attn`（只在 FM-4 和 FM-7 显示）；
   - `action_out_proj → v_k 板`；`v_k 板 → x_{k+1} 板`（Euler）；
   - `x_{k+1} → 回环`（按 §3 选定的方案）。
3. 联合注意力连线只画当前步、当前层。透明度按真实的 mass 设置，不常驻。
4. 第一块（入口）的清单维持现状：`posEmbed` 已删，三个专家输入都有源块。

## 6. 参考手法 → 我们的转译

- **Euler = 残差**：时间轴上的 10 块板，加上每块板旁的 v，构成"10 层残差网络"的空间隐喻。不画"残差流"的通用示意图。
- **Roelants 速度场热力图**：t × 维度的热力图，行是 t_k（10 行），列是 23 维，值为 mean_steps|v_k|。全部是真值。
- **粒子搬运**：只用真实的 8 条轨迹，不生成假粒子。
